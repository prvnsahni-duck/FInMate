# Recurring Expenses — Deferred Follow-ups

Status: the recurring-expense feature is **complete for beta** (see Release note
below). The items here are **non-blocking** engineering follow-ups captured
during architectural review. Do not implement any of them without first
reproducing a defect (items 1, 3) or making a product decision (item 2).

---

## 1. Review timezone / date arithmetic

**Priority:** Medium — only act on a reproducible bug.

`advanceDate()` in `backend/src/app/expenses/services/recurring-expenses.scheduler.ts`
parses `new Date('YYYY-MM-DD')` as UTC midnight, mutates with **local**
`setDate/setMonth`, then re-serializes via `toISOString().slice(0, 10)`.
`todayStr` (both the scheduler and `RecurringExpensesService.todayStr()`) uses
UTC. This mixed UTC/local handling can shift an occurrence by a day near
midnight or in non-UTC offsets.

Repro cases to capture before changing anything:

- User in UTC+5:30 and in UTC−8.
- Creation between 23:55 and 00:05 local time.
- DST transitions (where applicable).

Do **not** refactor the date logic speculatively before beta — only if an
off-by-one is actually observed.

---

## 2. Define month-end recurrence behavior (29th–31st)

**Priority:** High (post-beta) — needs a product decision first.

Monthly advance uses JS `setMonth(+1)`, which overflows: e.g. **Jan 31 → Mar 3**
(not Feb 28). Leap years compound this.

Decide the intended rule before coding:

- Last day of month, or
- Same calendar day when valid (skip/clamp invalid), or
- Skip invalid dates.

Do **not** "fix" the arithmetic until the expected behavior is defined.

---

## 3. Verify template lifecycle after group/member removal

**Priority:** High — track and verify; fix only if a real defect surfaces.

No explicit guard was found ensuring a template stops generating when its
references become invalid. Verify the scheduler does not keep materializing
expenses against dangling references for:

- Group deleted
- Group archived
- Member removed
- Payer removed (`paidByUser` / `paidByGroupMember`)

Expected: templates are paused/completed, or generation skips and logs — never
generates against invalid references.

## Release note (beta)

> **Recurring Expenses:** Completed for beta. Users can create personal and
> group recurring expenses. Templates are stored securely using the existing
> zero-knowledge model. If a recurring expense starts today, the first
> occurrence is generated immediately and appears in the ledger; future
> occurrences continue to be generated by the scheduler. Three non-blocking
> follow-up items (timezone handling, month-end recurrence rules, and template
> lifecycle after group/member removal) have been deferred for post-beta review.
